Yantra Commons is entirely community-driven. Every schematic, PCB layout, firmware file, and build guide you find here was created by volunteers who believe hardware should be open, reproducible, and free for anyone to study, build, and improve. There are many ways to get involved — whether you're a seasoned hardware engineer, a firmware developer, a technical writer, or simply someone who enjoys building things and wants to give back.

## Ways to Contribute

<CardGroup cols={2}>
  <Card title="Design Hardware" icon="microchip">
    Submit a new open hardware project or improve an existing one — schematics, PCB layouts, enclosures, and more.
  </Card>
  <Card title="Write Firmware" icon="code">
    Contribute code to any Yantra Commons project: bug fixes, new features, driver support, or platform ports.
  </Card>
  <Card title="Improve Docs" icon="pen-to-square">
    Fix typos, clarify assembly steps, add missing details, or translate build guides into other languages.
  </Card>
  <Card title="Test and Report" icon="wrench">
    Build a project from the published files, then report issues, suggest improvements, or share your build log with the community.
  </Card>
</CardGroup>

## Before You Start

- Read the [Design Guidelines](/contributing/design-guidelines) to understand the file formats, naming conventions, and quality standards expected of all contributions.
- Check existing issues and pull requests in the relevant repository before starting work — someone may already be addressing the same problem.
- For large or structural changes, open a GitHub issue or start a discussion first so the community can align on the approach before you invest significant time.
- Join the community forum and introduce yourself — it's a great way to find collaborators and get early feedback on your ideas.

## The Contribution Process

<Steps>
  <Step title="Fork the relevant repository on GitHub">
    Navigate to the Yantra Commons GitHub organisation and fork the repository for the project you want to contribute to.
  </Step>
  <Step title="Make your changes">
    Work in your fork, following the [Design Guidelines](/contributing/design-guidelines) for file formats, naming conventions, schematic quality, and documentation standards.
  </Step>
  <Step title="Test your changes">
    Build it, flash it, and document it. Contributions that include evidence of real-world testing are reviewed much more quickly.
  </Step>
  <Step title="Open a pull request">
    Submit a pull request against the upstream repository with a clear description of what changed and why. Reference any related issues.
  </Step>
  <Step title="Respond to feedback from reviewers">
    Maintainers and community members may ask questions or request changes. Stay engaged and address feedback promptly.
  </Step>
  <Step title="Get merged and published">
    Once your pull request is approved, it is merged and your contribution becomes part of the published project — credited to you.
  </Step>
</Steps>

<Tip>
  First-time contributor? Look for issues tagged `good first issue` in any Yantra Commons repository — these are specifically chosen as approachable starting points that don't require deep familiarity with the full project.
</Tip>

Ready to dive deeper? Read the [Design Guidelines](/contributing/design-guidelines) to make sure your files meet our standards, or jump straight to [Submit a Project](/contributing/submitting-a-project) if you have a complete design to share.
